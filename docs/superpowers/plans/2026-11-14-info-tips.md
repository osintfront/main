# Info Tips Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A small (i) with a 1–2 sentence explanation beside every map style, intelligence layer and sub-layer, in Hebrew and English.

**Architecture:** Reuse `src/components/common/InfoTip.tsx`. All texts are fixed strings in `src/i18n/en.ts` / `he.ts` under `info.*`; one registry file lists the keys so a unit test can check them. The (i) always sits beside a control, never inside a `<button>` or `<label>`.

**Tech Stack:** React, TypeScript, Tailwind, lucide-react, node:test, Playwright (mock build, like `tests/e2e/filter-sets.mock.cjs`).

**Spec:** `docs/superpowers/specs/2026-11-14-info-tips-design.md`

## Global Constraints

- Front-end only: no migration, no Edge Function, no AI call, no new dependency.
- Do not change which layers exist, their order, defaults, plan locks or labels.
- Each text: short sentences, at most 160 characters per language (the limit the test enforces).
- Use the texts in the table below verbatim (wording polish allowed only inside the limits; no new facts).
- No Hebrew string literals in components: texts come from `he.ts` / `en.ts` only.
- Existing keys `info.label`, `info.eei`, `info.severity`, `info.weather`, `info.infra`, `info.military` stay unchanged.
- Branch `feat/info-tips`. No merge to `main` and no deploy without the owner's yes.

## Review Focus

1. Tooltip near a screen edge on a 390 px phone, Hebrew (RTL) and English: it must be fully inside the viewport. → Task 2 test + Task 4 e2e.
2. Tooltip inside the scrolling Intelligence panel and the 208 px style menu: must not be cut by `overflow`. → Task 4 e2e (bounding box inside viewport and visible on top).
3. Tap on (i) beside a locked layer as a guest: shows the text, does not open the sign-up / upgrade window, does not turn the layer on. → Task 4 e2e (guest run).
4. Tap on (i) in the style menu: the menu stays open and the style does not change. → Task 4 e2e.
5. Opening a second tip closes the first (never two open). → Task 4 e2e.

**Interfaces:**
- Consumes: `InfoTipKey` from Task 1.

  - `InfoTip({ text?, tip?, className?, align? })` — `tip?: InfoTipKey`; when given, the text is `t(tip)` and the button carries `data-info-tip={tip}`; old callers passing `text` keep working (`data-info-tip=""`).
  - `WithTip({ tip, children, className? }: { tip: InfoTipKey; children: ReactNode; className?: string })` — a flex row: `children` in a `min-w-0 flex-1` box, then `<InfoTip tip={tip} />` as a sibling. Exported from the same file.
